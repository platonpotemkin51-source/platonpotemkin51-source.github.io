# 🌲 Общий обзор системы

**WoodFlow** автоматизирует полный жизненный цикл учета пиломатериалов на производстве и складе: от приемки готовой пачки до её калькуляции, резервирования под конкретного контрагента и физической отгрузки в транспортное средство (контейнер/автомобиль).

Приложение построено на стеке **Flask + SQLAlchemy (SQLite/PostgreSQL) + Flask-Login + WTForms (CSRF)**.

## 🔄 Жизненный цикл данных (Workflow)

Процесс движения номенклатуры в системе можно разделить на три ключевых этапа:

1. **Поступление на склад (`WoodPack`)**: Пачка регистрируется в системе со статусом `на_складе`. На основе физических замеров скрипт автоматически рассчитывает 4 вида объема и 4 вида веса.
2. **Формирование брони (`Booking`)**: Менеджер создает заказ (бронь) для клиента. К этой брони «привязываются» нужные пачки со склада. Статус пачек меняется на `забронирована`. Все объемы и стоимости суммируются в карточке заказа.
3. **Отгрузка (`Shipment`)**: При подъезде машины бронь закрывается, создается транспортная накладная с указанием номеров авто, контейнера и пломб. Статус брони и всех связанных пачек меняется на `отправлена`. Данные уходят в архив.

## 📊 Математика и бизнес-логика расчетов

В коде заложены жесткие отраслевые коэффициенты:

* Коэффициент плотности древесины (`pl`): **$630.0 \text{ кг/м}^3$**.
* Коэффициент ширины/усушки для таможни (`k_sh`): **$0.92$**.

### Формулы калькуляции одной пачки (`WoodPack`):

Система разделяет два ключевых направления учета: **для Покупателя (пок)** и **для Таможни (там)**. Внутри каждого направления считаются *фактические* (физические) и *номинальные* (зачетные) показатели.

* **Учет для покупателя (поштучный расчет доски):**
* `Номинальная ширина` = Фактическая ширина доски $- 3 \text{ мм}$
* `Номинальная толщина` = Фактическая толщина доски $- 3 \text{ мм}$
* $Объем\ номинальный\ (пок) = Ширина\ (ном) \times Толщина\ (ном) \times Длина\ (ном) \times Кол-во\ досок \times 10^{-9}$
* $Объем\ фактический\ (пок) = Ширина\ (факт) \times Толщина\ (факт) \times Длина\ (факт) \times Кол-во\ досок \times 10^{-9}$


* **Учет для таможни (пакетный расчет по габаритам пачки):**
* $Объем\ фактический\ (там) = Ширина\ пачки\ (факт) \times Толщина\ пачки\ (факт) \times Длина\ пачки \times 10^{-9}$
* $Объем\ номинальный\ (там) = Объем\ фактический\ (там) \times 0.92$



> **Вес** во всех 4 случаях рассчитывается идентично: $Объем\ (м^3) \times 630$.

## 🛠️ Подробный разбор функциональных модулей

### 1. Модуль аутентификации и разграничения прав (AUTH)

Безопасность реализована через сессии Flask-Login. Пользователи делятся на две роли: **Менеджер** и **Администратор**.

* Специальный декоратор `@admin_required` закрывает доступ к критическим секциям (панель аналитики, управление пользователями).
* При входе проверяется флаг `is_active_user`. Деактивированный админом сотрудник войти не сможет.

### 2. Главная панель и Аналитика (DASHBOARD)

Доступен только администраторам. Собирает сводные данные на лету с помощью SQL-функций агрегации (`func.sum`, `func.coalesce`):

* Расчет выручки за текущий месяц и текущий год на основе данных из таблицы `Shipment`.
* **API-эндпоинты (`/api/...`)**: Отдают данные в формате JSON для динамического построения графиков на фронтенде (динамика выручки по дням/месяцам, объем отгрузок, распределение остатков на складе по ширине доски).

### 3. Управление складом (STOCK)

Позволяет фильтровать пиломатериалы по ширине доски и статусу, поддерживает пагинацию (по 25 пачек на страницу).

* При добавлении пачки (`/stock/add`) менеджер вводит базовые параметры, а серверная часть берет на себя всю рутину по перемножению кубатуры и веса.
* Реализована валидация на статус: редактировать или удалить можно только ту пачку, которая физически лежит на складе (`на_складе`). Забронированный или уехавший товар изменить нельзя.

### 4. Модуль бронирования (BOOKINGS)

Обеспечивает сборку заказа для отправки.

* **Генерация номера**: Функция `generate_booking_number` автоматически создает красивый уникальный индекс вида `БР-2026-0001`, проверяя последний номер текущего года в базе данных.
* **Привязка пачек**: При добавлении пачки в бронь приложение выполняет транзакцию: меняет статус пачки и инкрементирует (наращивает) общие поля объема, веса и итоговой стоимости (`total_price`) в модели `Booking`.
* При отмене брони происходит обратный процесс — пачки освобождаются, а статус заказа меняется на `отменена`.

### 5. Логистика и Архив (SHIPMENT & ARCHIVE)

Переводит финансовое обязательство в физическую отгрузку.

* К брони прикрепляются данные транспорта: номер машины, прицепа, контейнера и пломбы.
* Система интегрирована с внешним модулем `excel_utils`. С помощью функции `send_file` менеджер может в один клик скачать готовую накладную в формате `.xlsx` для печати водителю или таможенному брокеру.

## 🗄️ Архитектура базы данных

В системе спроектированы 4 взаимосвязанные таблицы:

| Таблица | Описание | Связи |
| --- | --- | --- |
| **`User`** | Пользователи системы (логины, хэши паролей `pbkdf2`, роли). | Один ко многим к `WoodPack`, `Booking`, `Shipment` (как создатель). |
| **`WoodPack`** | Атомная единица учета (геометрия, объемы, статусы пачки). | Многие к одному с `Booking` через `booking_id`. |
| **`Booking`** | Заказ/Машина (данные контрагента, общие объемы, цены). | Один к одному с `Shipment`. Один ко многим с `WoodPack`. |
| **`Shipment`** | Транспортный узел (номера машин, пломб, дата фактического убытия). | Один к одному с `Booking` через `booking_id`. |

## 🎯 Инициализация системы

При первом запуске приложение автоматически:

1. Создает файл базы данных (если его нет) со всей структурой таблиц (`db.create_all()`).
2. Проверяет наличие администратора. Если база пуста, создается дефолтный суперпользователь: `admin` / `admin123`.
3. Гарантирует наличие папки для экспорта Excel-отчетов.
