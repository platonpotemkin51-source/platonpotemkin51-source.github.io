## 2. Самостоятельная работа: Исследование других моделей (kNN, SVM) и работа с LLM
Была предпринята попытка улучшить метрики с помощью альтернативных классических алгоритмов: метода k-ближайших соседей (kNN) и метода опорных векторов (SVM). Предварительно данные были нормализованы с помощью `StandardScaler`.

**Результат:** Классические алгоритмы kNN и SVM показали результаты метрики ROC-AUC ниже, чем у `RandomForestClassifier`.

**Обоснование (сформулировано с помощью LLM-ассистента):**
Достичь более высокой точности с помощью kNN и SVM на данных кредитного скоринга крайне сложно по ряду математических причин:
1. **Природа табличных данных:** kNN и SVM работают в непрерывном геометрическом пространстве и измеряют математические расстояния. Категориальные (закодированные) и бинарные признаки в таком пространстве теряют смысл, тогда как алгоритмы на основе деревьев (Случайный лес) отлично работают с логическими условиями («больше/меньше», «равно/не равно»).
2. **Размерности:** При большом количестве признаков расстояния между любыми двумя клиентами в kNN становятся примерно одинаковыми, что размывает предсказания.
3. **Нелинейность:** SVM пытается провести гиперплоскость для разделения классов. В кредитных данных граница между «хорошим» и «плохим» заемщиком имеет сложную, нелинейную, ступенчатую структуру, которую деревья улавливают лучше.
4. **Дисбаланс классов:** Деревья решений гораздо более устойчивы к тому факту, что дефолтов в выборке значительно меньше, чем возвратов.

Для получения **наивысшей точности (ROC-AUC > 0.90)** был использован алгоритм градиентного бустинга — **CatBoostClassifier** (или `HistGradientBoostingClassifier`), который является индустриальным стандартом для подобных задач и значительно превосходит базовый Random Forest.

## 3. Анализ современных алгоритмов 
Изучение актуальных соревнований научных статей (в том числе предложенную статью на Kaggle) показывает, что в 2023-2025 годах в задачах классификации табличных данных по мимо классического случайного леса и логистической регресии доминируют методы на основе **Градиентного бустинга над деревьями решений (GBDT)**.

Основные используемые алгоритмы:
* **XGBoost:** Классика соревнований. Оптимизированный распределенный градиентный бустинг, который отлично справляется с разреженными данными.
* **LightGBM (от Microsoft):** Отличается высокой скоростью обучения и низким потреблением памяти. Является алгоритмом выбора №1 для огромных датасетов (миллионы строк).
* **CatBoost (от Yandex):** Алгоритм, который «из коробки» идеально обрабатывает категориальные признаки без необходимости делать One-Hot Encoding, а также имеет мощную защиту от переобучения.
* *Нейронные сети (TabNet):* Применяются реже, так как сложнее в настройке, дольше обучаются и часто уступают бустингу на табличных данных средних размеров, однако используются в гибридных ансамблях для выбивания последних долей процентов метрики.

## 4. Интеграция обученной модели с веб-сервисом
Чтобы предсказаниями модели (например, CatBoost или RandomForest) могли пользоваться другие приложения (фронтенд сайта банка, мобильное приложение), модель необходимо развернуть в виде REST API сервиса. 



**Пошаговый алгоритм интеграции (на примере FastAPI / Flask):**

1. **Сериализация (Сохранение) модели:**
   В Colab-ноутбуке обученная модель сохраняется в файл на диск с помощью библиотеки `joblib` или `pickle`.
   *Код:* `joblib.dump(model, 'credit_model.pkl')`
2. **Создание окружения и структуры проекта на сервере:**
   На бэкенд-сервере устанавливается Python, фреймворк (FastAPI или Flask), `pandas`, `scikit-learn` и создается файл `app.py`.
3. **Инициализация веб-приложения и загрузка модели:**
   При старте сервера (до того как придут запросы) модель загружается в оперативную память.
   *Код:* `model = joblib.load('credit_model.pkl')`
4. **Описание схемы данных (для FastAPI):**
   С помощью библиотеки `Pydantic` описывается структура JSON, которую должен прислать пользователь (возраст, пол, доход и т.д.). Это обеспечивает валидацию входящих данных.
5. **Создание маршрута (Endpoint):**
   Пишется функция-обработчик для POST-запросов (например, по пути `/predict`).
   * Алгоритм функции:
     1. Получить JSON от клиента.
     2. Конвертировать JSON в формат `pandas.DataFrame` (в 1 строку).
     3. Передать DataFrame в метод `model.predict()` (или `predict_proba()`).
     4. Упаковать ответ (0 или 1, или процент вероятности) обратно в JSON.
6. **Возврат ответа:**
   Отправка ответа клиенту. Пример ответа: `{"status": "success", "default_prediction": 0, "probability": 0.12}`.
7. **Запуск сервера:** Приложение запускается через ASGI-сервер (например, `uvicorn app:app --host 0.0.0.0 --port 8000`).
