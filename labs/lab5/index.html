    Отчет по проекту: «Предсказание цен на недвижимость»

    https://drive.google.com/file/d/1kihJn3aL9FOzEX-llcChrjFvmNCRN_OZ/view?usp=sharing

    Цель проекта: Прогнозирование стоимости домов в округе Кинг (штат Вашингтон, США) на основе исторических данных о продажах с использованием алгоритмов машинного обучения.

    1. Базовая часть: подготовка данных и первичные модели

    В ходе базовой части работы были загружены и проанализированы тренировочные (15 129 объектов) и тестовые (6 484 объекта) наборы данных.

    Для первичной оценки были обучены две базовые модели машинного обучения:

    • Линейная регрессия (Linear Regression): MAE: 126 852.51, RMSE: 201 883.24
    • Случайный лес (Random Forest Regressor, базовая версия): MAE: 70 766.57, RMSE: 136 780.94

    Случайный лес "из коробки" показал существенно более высокие результаты как визуально (по кросс-плоту), так и по метрикам ошибок.

    2. Анализ значимости признаков (Feature Importance)

    При анализе весов признаков базовой модели Random Forest были выделены:

    • Наиболее значимые параметры: Жилая площадь (0.307), Оценка риелтора (0.287), Широта (0.172), Долгота (0.071), Вид на воду (0.030). (Местоположение квартиры и её площадь играют ключевую роль в ценообразовании).
    • Наименее значимые параметры: Год реновации (содержит много пропусков/нулей), Количество этажей, Состояние, Спальни.

    3. Самостоятельная исследовательская работа

    В рамках самостоятельного этапа проекта были предприняты попытки улучшить качество предсказаний:

    Эксперимент 1: Исключение слабых признаков

    Были удалены 4 наименее информативных признака: ['Год реновации', 'Количество этажей', 'Состояние', 'Спальни'].

    • Результат: MAE: 71 350.62, RMSE: 135 054.09.
    • Вывод: Метрики изменились незначительно (RMSE немного уменьшилась по сравнению с базовым лесом, MAE чуть выросла). Это подтверждает гипотезу, что удаленные признаки практически не содержали полезного сигнала (являлись информационным шумом). Модель стала легче, не потеряв при этом в качестве.

    Эксперимент 2: Подбор гиперпараметров (GridSearchCV)

    Для модели Random Forest был проведен автоматический поиск лучших гиперпараметров по заданной сетке значений с применением кросс-валидации (CV=3).

    • Лучшие параметры: {'max_depth': 20, 'min_samples_leaf': 1, 'n_estimators': 200}
    • Результат: MAE: 70 701.41, RMSE: 135 836.69.
    • Вывод: Ошибка RMSE снизилась примерно на 1000 пунктов по сравнению с базовой версией. Увеличение количества деревьев и ограничение глубины немного улучшили обобщающую способность алгоритма.

    Эксперимент 3: Применение градиентного бустинга (XGBoost)

    Для достижения максимальной точности была обучена модель XGBoost — один из самых мощных алгоритмов для табличных данных.

    • Параметры: n_estimators=300, learning_rate=0.05, max_depth=6.
    • Результат: MAE: 67 233.20, RMSE: 124 935.55.
    • Вывод: Градиентный бустинг уверенно обошел случайный лес, показав самую низкую ошибку среди всех протестированных моделей. Именно эту модель рекомендуется использовать в продакшене.

    4. План интеграции с веб-сервисом (MLOps)

    Для того чтобы модель могла приносить пользу бизнесу в реальном времени, был разработан пошаговый план развертывания REST API с использованием фреймворка FastAPI:

    1. Сохранение готовой модели: Использование библиотеки joblib для дампа обученной модели XGBoost в файл model.pkl.
    2. Настройка веб-среды: Подготовка виртуального окружения, установка fastapi, uvicorn, xgboost.
    3. Написание логики приложения (main.py):
    4. Инициализация приложения и загрузка model.pkl при старте.
    5. Описание Pydantic-схемы для валидации входящих JSON-данных от клиента (метраж, гео-данные и т.д.).

    6. Написание POST-эндпоинта (например, /predict), который принимает данные, подает их в метод predict() загруженной модели и возвращает спрогнозированную цену.

    7. Запуск и проверка: Локальный запуск сервиса (uvicorn main:app --reload) и тестирование эндпоинта через встроенный UI Swagger.

    Итог

    Бизнес-задача успешно выполнена. Лучшей моделью стал XGBoost. Сформирован четкий пайплайн подготовки данных, отбора фичей и дальнейшего деплоя модели в виде микросервиса.
