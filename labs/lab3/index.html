    Отчет по автоматическому развертыванию статического сайта

    1. Результаты выполнения (Ссылки)

    Не забудь заменить данные в скобках на свои реальные логины и названия.

    1. Сайт на Sourcecraft: https://spbsvu3skype2.sourcecraft.site/portfolio/
    2. Репозиторий на Sourcecraft: https://sourcecraft.dev/spbsvu3skype2/portfolio
    3. Сайт на GitHub Pages: https://platonpotemkin51-source.github.io/
    4. Репозиторий на GitHub: https://github.com/platonpotemkin51-source/platonpotemkin51-source.github.io

    2. Какие действия были выполнены

    • Инициализирован проект MkDocs, а исходные файлы конфигурации настроены для генерации статики.
    • Создан файл requirements.txt с фиксацией необходимых зависимостей (включая тему mkdocs-material и плагин mkdocs-git-revision-date-localized-plugin, чтобы избежать ошибок сборки).
    • В локальный Git-репозиторий добавлен второй удаленный адрес (remote) платформы Sourcecraft командой git remote add sourcecraft.
    • Настроен деплой для GitHub Pages с использованием стороннего экшена mhausenblas/mkdocs-deploy-gh-pages@master в директории .github/workflows/.
    • Настроен изолированный CI/CD пайплайн для Sourcecraft (в файле .sourcecraft/ci.yaml), который запускает Docker-контейнер с Python, устанавливает зависимости, собирает сайт и принудительно пушит готовую статику в ветку release.
    • Настроена конфигурация .sourcecraft/sites.yaml для указания платформе Sourcecraft источника файлов для публикации сайта.

    3. Как организован репозиторий

    Структура репозитория выстроена так, чтобы оба CI/CD-сценария могли корректно находить исходники и конфигурации:

    .
├── docs/ 
├── numpy_lb/                    # Лаборабораторное задание
├── source/                      # Исходные Markdown-файлы сайта (docs)
│   └── mkdocs.yml               # Главный конфигурационный файл MkDocs
├── requirements.txt             # Список Python-библиотек и плагинов для сборки
├── .github/
│   └── workflows/
│       └── actions.yml           # CI/CD сценарий деплоя для GitHub Actions
├── .sourcecraft/
│   ├── sites.yaml               # Указание ветки (release) и папки (site) для хостинга
│   └── ci.yaml                  # Сценарий автоматической сборки для Sourcecraft
└── .gitignore                   # Исключение служебных файлов из коммитов

    4. Что необходимо сделать, чтобы выполнить деплой

    Поскольку настроена полная автоматизация, для обновления сайтов достаточно выполнить стандартные команды Git в локальном терминале (или через интерфейс IDE):

    1. Внести изменения в текст (например, в Markdown-файлы).
    2. Зафиксировать изменения: git add . и git commit -m "обновление контента".
    3. Отправить изменения на GitHub: git push origin main
    4. Отправить изменения на Sourcecraft: git push sourcecraft main

    После этого платформы автоматически запустят сборку и обновят сайты по ссылкам.

    5. Настройки репозиториев (GitHub и Sourcecraft)

    Для успешной работы пайплайнов в веб-интерфейсах платформ были выполнены следующие настройки:

    Настройки GitHub: * Workflow permissions: В разделе Settings -> Actions -> General установлены права Read and write permissions, чтобы скрипт мог сохранять (пушить) собранный сайт обратно в репозиторий (ветку gh-pages). * GitHub Pages: В разделе Settings -> Pages в качестве источника (Source) указано Deploy from a branch, выбрана ветка gh-pages и папка /(root).

    Настройки Sourcecraft: * Авторизация для Push: Предварительно сгенерирован персональный токен (PAT) с правами Maintainer. * Секреты CI/CD: В настройках репозитория в разделе CI/CD -> Секреты (Переменные) создана переменная с именем SC_TOKEN, куда помещен сгенерированный токен. Это позволило пайплайну авторизоваться и сделать пуш собранного сайта в ветку release. * Sourcecraft Sites: Наличие файла .sourcecraft/sites.yaml в корневой директории автоматически включило службу хостинга для данного репозитория.
